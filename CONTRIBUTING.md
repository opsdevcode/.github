# Contributing (OpsDevCode)

Canonical company contribution path for **first-class** repositories.

Product-specific rules (gates, language toolchains, Netlify previews) stay in
the product repo. This document is the company process.

Generated / goldpath repositories are **not** this path. See
[docs/engineering-foundations.md](docs/engineering-foundations.md#generated-repositories).

## How to make a change

1. Branch from `main`
2. Make a focused change
3. Use [Conventional Commits](https://www.conventionalcommits.org/)
4. Run the **repo’s** local checks
5. Push the branch
6. Open a pull request (PR required)
7. Required CI must pass
8. Resolve review conversations
9. Squash-merge (unless a documented exception)
10. GitHub deletes the head branch

You should not need a different process per product. Differences are **profile
plus required check names**, not ad-hoc branch protection.

## Tool-vendor authorship

Tool-vendor or AI authorship footers are not used in OpsDevCode commits,
pull requests, repository READMEs, or product surfaces.

Do not add `Created with Cursor`, `Made-with: Cursor`, `Co-authored-by:` naming
an assistant, `Generated by AI`, or similar. Authorship is OpsDevCode (or the
human contributors named in git history).

Legitimate technical references to tools (Cursor as an IDE or MCP client,
evaluations, compatibility) are allowed. Product provenance such as
`Generated by Repave blueprint` is allowed.

## Security reports

Do not file public issues for vulnerabilities.

Use GitHub Security Advisories on the affected repository or
**security@opsdevcode.com**. See [SECURITY.md](SECURITY.md).

## Architecture decisions

Durable decisions that affect product boundaries, persistence, APIs, security,
deployment architecture, major capability contracts, or irreversible
infrastructure belong in an **ADR** in the owning product repo (or this repo
for org-wide GitHub/governance decisions).

Convergence is not an OpsDevCode ADR repository.

Do not write an ADR for every small change.

## Profiles

| Profile | Repos | Approvals (solo now) | Target |
| --- | --- | --- | --- |
| product | Repave, Overpass, Toll, Dispatch, Relay | 0 | 1 when a second maintainer exists |
| infra | `repave-aws-infra` | 0 | 1 |
| web | `opdevcode-website` | 0 | CODEOWNERS *request* reviews; review is not a merge deadlock |
| docs | Convergence | 0 | PR + CI |
| org-meta | `.github` | 0 | PR + `validate` |

## Merge

Squash only. Merge commits and rebase merges are disabled so one PR is one
mainline change. Auto-merge **capability** is on; do not enable auto-merge on
a PR unless you intend it.

## Bypass

No `RepositoryRole` admin `always` bypass. Direct pushes to `main` are not the
workflow.

Automation that previously pushed `main` (Repave Release changelog, infra
`DEPLOY_BUMP_TOKEN` image pins) must open a PR or use a **dedicated GitHub App**
installed on the org. GitHub Actions cannot be added as a ruleset bypass actor
in this org (API 422).
