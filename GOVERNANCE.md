# OpsDevCode repository governance

This document is the **desired** organization policy for GitHub repositories.
It is not a snapshot of today’s accidents. Enforcement is later; this repository
holds the declaration and a **read-only** drift checker.

The organization profile README (`profile/README.md`) stays marketing-facing.
Do not treat it as the governance spec.

## Repository classes

| Profile | Name | Purpose |
| --- | --- | --- |
| **A** | Product / service | Commercial products and the internal Relay runtime. Shared PR/CI/security baseline; **domain CI stays local**. |
| **B** | Infrastructure | Environment deployment and IaC. Stronger review; no application semver-release assumptions. |
| **C** | Web | Company site. Preview/production safety; versioning need not be python-semantic-release. |
| **D** | Documentation / methodology | Convergence. Public collaboration; content checks, not app deploy. |
| **E** | Organization metadata | This repository: policy, advisory audit, future community-health defaults and small reusable workflows. |
| **F** | Generated / bootstrap / demo | Repos emitted by Repave (Terraform, Helm, OPA, Checkov, Ansible, GitOps demos). **Not** commercial products. Lightweight policy. |

Assignments live in [`profiles/assignments.json`](profiles/assignments.json).
Class definitions live in [`profiles/classes.json`](profiles/classes.json).

### Profile F identification (later)

Do **not** auto-classify every `tf-*` name in this phase. Future identification may use:

- description prefixes such as `Generated by repave` or `Bootstrap`
- a maintained allow/deny list
- tags/topics once the org uses them

Until a repo is assigned profile F, the checker does not treat it as a product.

## Visibility policy

Visibility that **matches** the assigned profile is **intentional policy, not drift**.

| Repository | Policy |
| --- | --- |
| `repave`, `overpass`, `toll`, `dispatch` | **private** (commercial product source) |
| `relay` | **private** (internal conversational runtime; not a public product) |
| `repave-aws-infra` | **private** |
| `opdevcode-website` | **public** (acceptable and current) |
| `convergence` | **public** |
| `.github` | **public** (org profile) |
| Generated (F) | **private by default** unless a repo is explicitly intended public |

This file does not change GitHub visibility. Public vs private differences are
deliberate when they match the table above.

## Canonical check vocabulary (target)

Future stable check **names** (GitHub Actions job `name:` / ruleset contexts):

| Name | Typical meaning |
| --- | --- |
| `quality` | lint, format, types |
| `test` | unit tests |
| `security` | SAST/dep audit appropriate to the stack |
| `build` | compile/image/chart build without publish |
| `integration` | slower or clustered tests |
| `release-check` | release dry-run / version policy |

This is a **target vocabulary**. Existing required check names (especially
Repave: `engine-unit`, `Python quality and security`, chart-smoke variants,
CodeQL language labels, `backstage-audit`, and similar) remain authoritative
until a dedicated migration updates **both** the workflow job names and the
ruleset in one controlled change. Do not rename Repave checks for aesthetics.

Product-specific jobs are allowed and expected (charts, operator, corpus).
Thin products should not copy Repave’s full gate.

## Ruleset baseline (target)

Desired for first-class repos (A–E), on the default branch:

- Pull request required to update `main`
- Force push prohibited
- Branch deletion prohibited
- Conversation resolution required
- Required status checks (profile-appropriate; names may still be local)
- No merge queue required

### Reviews by profile

The org may be **solo-operated**. Policy must not block that before there are
multiple maintainers.

| Profile | Review target |
| --- | --- |
| A | PR required. Approving-review count **0** is allowed while solo. Prefer 1 when a second maintainer exists. |
| B | PR required. Approving-review count **1** when a second reviewer exists; **0** is an explicit solo exception, not the long-term infra bar. |
| C | PR required. CODEOWNERS and/or 1 approval when maintainers exist. |
| D | PR required. Approving-review count **0** is compatible with public docs. |
| E | PR required once this repo is protected (follow-up). |
| F | Lightweight: PR preferred; do not inherit Repave’s full check matrix. |

Bypass actors (admin role always-on, named-user bypass) are **migration-era**.
Tighten deliberately; do not encode today’s bypass map as the desired end state.

This phase **does not create or edit rulesets**.

## Security baseline (target)

**Required (when the GitHub plan exposes the feature):**

- Secret scanning
- Push protection
- Dependabot alerts
- Workflows default to least privilege; prefer `permissions: contents: read`

**Recommended where justified** (plan, language, and deploy surface):

- Dependency review on pull requests
- CodeQL or equivalent SAST
- Container image scanning
- Attestations / SBOM
- Cloud OIDC instead of long-lived keys

Do not mandate Advanced Security suites on every repo. Unavailable API fields
are **UNKNOWN**, not drift.

Organization **2FA** is an org-admin control, not a repository setting. It is
called out under [Organization administration](#organization-administration).
Do not mix 2FA enablement into repository-policy PRs.

## Build and CD ownership

**Product/service repositories own build and immutable artifact publication.**  
**The infrastructure repository owns environment deployment and promotion.**

Canonical artifact identity is **git SHA and/or semver**. A floating `:latest`
tag may exist during transition; it is not the deployment identity.

Known **transitional** exceptions (do not “fix” in this repository):

- Overpass publishes images and dispatches `overpass-release` to `repave-aws-infra` (handoff matches the rule).
- Repave publishes and dispatches `repave-release` (handoff matches the rule).
- Toll and Dispatch publish images today without a complete infra deploy owner.
- Relay is not yet deployed as the canonical internal runtime.
- Website production is Netlify-gated, not EKS.

## Drift policy

Governance is **declarative** (`profiles/`) and **periodically audited**.

`scripts/audit-github-governance.sh` is **read-only** and **advisory**. Drift
does not change GitHub. Do not churn product repos solely to make the checker
green until an explicit enforcement PR.

## Future reusable workflows (not in this change)

Small callables only; no internal CI framework:

- Python quality (Ruff/mypy or repo-equivalent)
- Python tests
- commitlint / semantic pull-request title
- optional container publish (SHA-immutable)

Repositories keep domain-specific jobs.

## Future enforcement (not executed here)

1. Protect `.github` `main`
2. Minimal rulesets for currently unprotected first-class repos
3. Enable baseline security settings (secret scanning, push protection, Dependabot alerts)
4. Normalize thin-product CI via reusable workflows
5. Migrate canonical check names **with** rulesets
6. Tighten bypass actors
7. Scheduled governance drift detection
8. Generated-repository (F) policy as its own change

## Organization administration

Separate from repository files:

- **2FA:** organization two-factor enforcement was observed **off**. Enabling it
  affects every member’s access. Treat as an org-admin action, not a repo PR.
- Org-level “GitHub recommended” code-security configuration may exist
  **unenforced**. Enabling it org-wide is a distinct admin decision.

## Checker

```bash
./scripts/audit-github-governance.sh
./scripts/audit-github-governance.sh --offline   # config only
```

Exit codes: `0` all assigned repos conform, `1` drift, `2` tool/API failure.
